# NeeDS フィジカルチェック

神戸のパーソナルトレーニングジム **NeeDS** のアスリート向けフィジカルチェック・アプリです。
紙の「NeeDSスコア記入用紙」の40項目をタブレットから入力すると、自動で採点し、
レーダーチャート・カテゴリー別スコア・気をつけたい点・推移グラフまで表示します。

- **体験者（初回）**：レーダーチャートで身体の「形」と伸びしろを見せる
- **既存会員（2回目以降）**：推移グラフで変化を見せる

公開URL： https://nakatsukasa111-tech.github.io/needs-athcheck/

---

## 1. 何がどこにあるか

| ファイル | 中身 |
|---|---|
| `index.html` | アプリ本体。この1ファイルで動きます（GitHub Pages で公開） |
| `apps-script/コード.gs` | Google Apps Script 側のコード。スプレッドシートに貼り付けて使います |
| `docs/CLAUDE_CODE_指示書.md` | 仕様書 |
| `docs/NeeDS_閾値マスタ_v1.xlsx` | thresholds / rules シートの元データ（列の形を確認する用の控え） |

```
GitHub Pages（index.html）
   ↓ fetch GET  → doGet   閾値の取得 / 会員検索 / 履歴取得
   ↓ fetch POST → doPost  会員登録 / 測定の保存
Apps Script（ウェブアプリとして公開）
   ↓
Google スプレッドシート（4シート）
   ├ members       会員マスタ
   ├ measurements  測定ログ
   ├ thresholds    閾値マスタ（数値を書き換えるところ）
   └ rules         判定ルール（数値を書き換えるところ）
```

**判定基準はコードの中に書いていません。** アプリは起動のたびに
`thresholds` と `rules` シートを読みます。スプレッドシートの数値を書き換えて保存すれば、
次にアプリを開いたときから新しい基準で判定されます。プログラムの修正は不要です。

## 2. 接続先はもう入っています

アプリには接続先（Apps Script のURLと合言葉）が最初から埋め込んであります。
**ふだんは何も設定せずに、URLを開くだけで使えます。**

変える必要があるのは、次のときだけです。

- Apps Script を作り直して、ウェブアプリURLが変わったとき
- `コード.gs` の `ACCESS_TOKEN`（合言葉）を変えたとき

そのときは、画面右上の **［接続設定］** から入力し直してください。
入力した内容はそのブラウザに保存され、次回からは入力不要です。
（元に戻したいときは、接続設定の中の［最初の設定に戻す］を押してください）

接続設定の画面は、貼り間違いをその場で直します。

- URLの末尾に付いた `?token=…&action=…` は自動で消します
- `/dev` で終わっていたら `/exec` に直します
- `AKfycb…` だけを貼り付けた場合は「これはデプロイIDです」と知らせます
- ［接続テストだけする］で、**URLが違うのか、合言葉が違うのか**を切り分けて表示します

## 3. Apps Script の準備（ここだけ手作業です）

初回だけ必要な作業です。ゆっくりやって15分ほどで終わります。

### 3-1. スプレッドシートを用意する

1. Google ドライブで新しいスプレッドシートを作り、名前を `NeeDS フィジカルチェック` などにする。
2. `docs/NeeDS_閾値マスタ_v1.xlsx` の **thresholds** と **rules** の内容を、
   同じ名前のシートとしてこのスプレッドシートに取り込む。
   （`ファイル` → `インポート` → `アップロード` → xlsx を選び、
   「新しいシートを挿入する」でインポート。シート名が `thresholds` `rules` になるよう直す）
   - シートの1行目は列名です。**列名と `item_key` / `sex` / `age_band` / `rule_key` は変えないでください。**
   - 書き換えていいのは `red_max` / `green_min` / `value` / `note` です。

### 3-2. コードを貼り付ける

1. スプレッドシートのメニューで `拡張機能` → `Apps Script` を開く。
2. 最初から入っている `function myFunction() {}` を全部消して、
   このリポジトリの `apps-script/コード.gs` の中身をまるごと貼り付ける。
3. 上のほうにある合言葉を確認する。

   ```js
   var ACCESS_TOKEN = 'NeeDS2026';
   ```

   ここを変えた場合は、アプリの［接続設定］の合言葉も同じ文字列に変えてください。
4. 保存（フロッピーのマーク、または `Ctrl`/`⌘` + `S`）。

### 3-3. シートを作る関数を1回だけ実行する

1. エディタ上部の関数名の欄で **`setupSheets`** を選び、`実行` を押す。
2. 初回は「承認が必要です」と出ます。
   `権限を確認` → 自分のGoogleアカウントを選ぶ → 「このアプリは確認されていません」と出たら
   `詳細` → `（プロジェクト名）に移動` → `許可` を押す。
   （自分で書いたコードなので問題ありません）
3. スプレッドシートに `members` と `measurements` のシートができていれば成功です。

### 3-4. ウェブアプリとして公開する

1. エディタ右上の `デプロイ` → **`新しいデプロイ`**。
2. 左上の歯車マーク → **`ウェブアプリ`** を選ぶ。
3. 設定を次のようにする。

   | 項目 | 選ぶもの |
   |---|---|
   | 説明 | `v1`（何でもよい） |
   | 次のユーザーとして実行 | **自分** |
   | アクセスできるユーザー | **全員** |

   > **ここが最大の落とし穴です。**「Googleアカウントを持つ全員」ではなく **「全員」** を選んでください。
   > 「Googleアカウントを持つ全員」だと、アプリからの通信が弾かれます。

4. `デプロイ` を押すと **ウェブアプリURL** が出ます。これをコピーします。

   ```
   ○ 正しい： https://script.google.com/macros/s/AKfycb.../exec
   × 違う  ： AKfycb...              ← これは「デプロイID」です
   × 違う  ： .../dev                ← これは自分専用の開発用URLです
   ```

5. このURLが、いまアプリに埋め込まれているURLと違う場合だけ、
   アプリの［接続設定］に貼り付けて［保存して接続する］を押してください。

### 3-5. コードを直したら、必ずデプロイし直す

**保存しただけでは、公開されているアプリは古いままです。**

1. `デプロイ` → `デプロイを管理`
2. 右上の **鉛筆マーク**
3. `バージョン` を **「新しいバージョン」** に変える
4. `デプロイ` を押す

この手順だと、ウェブアプリURLは変わりません。
（`新しいデプロイ` から作り直すとURLが変わるので、アプリ側の設定も直す必要があります）

デプロイし直したかどうかは、アプリの［接続設定］→［接続テストだけする］で確認できます。
`コード.gs` の `API_VERSION` に書いた文字列が表示されます。

## 4. 使い方

### 画面1：選手を選ぶ
名前・かな・会員番号の一部を入れると候補が出ます。選ぶと履歴を読み込んで測定画面に進みます。
初めての選手は下のフォームから登録してください。会員番号（`NDS0001` 形式）は自動で振られます。

> 履歴は名前ではなく会員番号で紐づけています。同姓同名や改姓があっても履歴が分断されません。

### 画面2：測定を入力
5つのタブ（柔軟性 / バランス / 筋力 / ジャンプ / 動きの質）に40項目が並びます。

- **測っていない項目は空欄（「未」）のままにしてください。** 空欄は採点の分母から外れます（0点にはなりません）。
- 柔軟性と動きの質は 0〜3 のボタン。**0点は「怪我などで測定不能」「痛みはないが病的な硬さがある」ときに使います。**
- 1RM系（BP / SQ / DL）は実測kgを入れてください。採点は体重比で行うので、**先に体重を入れてください。**
  聞き取りや推定で入れた値は「推定」にチェックを入れると、推移グラフで点線と白い点に区別されます。
- ホップテストとドロップジャンプは、**測定機器が出したRSI値をそのまま**入れてください。

### 画面3：結果を見る
レーダーチャート → 総合スコアとカテゴリー別バー → ジャンプの中身 → 気をつけたい点 →
項目ごとの結果 → 推移グラフ の順です。上部のセレクトで、次を切り替えられます。

| 切り替え | 中身 |
|---|---|
| 主役 | レーダーチャートを大きく見せるか、総合スコアを大きく見せるか |
| レーダーの軸 | 5軸すべて描くか、測定した軸だけで描くか（体験時に軸が潰れる場合に使います） |
| 解説の書き方 | 事実ベース（「機能していません」）か、伸びしろ重視（「ここが伸びれば全体が変わる」）か |

選んだ状態はそのブラウザに記憶されます。

## 5. 採点の考え方

| 対象 | やり方 |
|---|---|
| 未入力 | 分母から除外（0点にはしない） |
| 柔軟性の左右差 | 種目スコアは**低いほうの点数**を採用。左右差は総合スコアに加算せず、フラグとして別に出す |
| 実測系 | `thresholds` の `red_max` 以下＝1点／`green_min` 以上＝3点／その間＝2点（`direction=low` にも対応） |
| 1RM | 保存は実測kg、採点は `1RM ÷ 体重` の体重比 |
| 得点率 | 合計点 ÷（入力済み項目数 × 3）× 100 |
| 色 | `rules` の `flex_green_min`（88.9%）以上＝緑、`flex_yellow_min`（66.7%）以上＝黄、それ未満＝赤 |
| 総合スコア | 5カテゴリーの得点率の加重平均（重みは `index.html` の `CATEGORY_WEIGHTS`。既定はすべて 1） |

ジャンプは種目間の関係も見ます。

- **SQJ → CMJ の伸び率**：反動（伸張反射）を使えているか
- **CMJ → ABJ の伸び率**：腕振り・上半身の連動が効いているか
- **SLCMJ**：両脚CMJの50%を目標値とする相対判定と、`thresholds` の `sl_cmj` による絶対値判定の**2軸**
- **左右差**：高いほうを100とした差が10%以上で赤フラグ（`sl_cmj` / `sl_sq` / `sl_stance` / `ground_touch_bal`）
- **RSI**：ホップとドロップの差が15%以上でフラグ。3.1以上は「非常に良い」と表示（色は緑のまま）

### 保存されるもの

`measurements` シートには、**実測値とスコアの両方**を保存しています。
推移グラフは保存済みスコアではなく、**保存された実測値をいまの基準で計算し直して**描きます。
そのため、`thresholds` を調整しても過去の推移が壊れません。
保存済みスコアは「そのとき選手にどう見せたか」の記録として残しています。

`age` / `age_band` / `lbm`（除脂肪体重）/ `session_no` は、アプリではなく Apps Script 側で計算しています。

## 6. 基準の数値を変えたいとき

スプレッドシートの `thresholds` / `rules` シートを直接書き換えて保存し、アプリを再読み込みしてください。

- `thresholds`：項目ごと・男女別・年齢区分別の `red_max` / `green_min`
- `rules`：色の境界、左右差フラグ、ジャンプの伸び率の基準、ジュニア／大人の境界（17歳）など

年齢区分は `adult`（17歳以上）と `junior`（16歳以下）です。
将来 `elementary`（小学生）を足すときは、`thresholds` に `age_band` が `elementary` の行を追加し、
`rules` に `age_band_border_elementary`（その年齢未満を elementary とする）を1行足してください。
アプリ側の改修は要りません（該当行がない項目は junior → adult の順に読み替えます）。

片脚立位と地面タッチは NeeDS 独自プロトコルで参照文献がないため、いまの値は仮置きです。
実測データが20〜30件たまった時点で、その分布から引き直す前提です。

## 7. 困ったときは

| 症状 | 見るところ |
|---|---|
| 「接続できていません」と出る | ［接続設定］→［接続テストだけする］。原因別のメッセージが出ます |
| 「合言葉が一致していません」 | `コード.gs` の `ACCESS_TOKEN` と接続設定の合言葉。直後なら**デプロイのし直し**も疑ってください |
| 「サーバーに届いていません」 | URLの間違い、または［アクセスできるユーザー］が「全員」以外になっている |
| 「Googleのログイン画面が返ってきています」 | ［アクセスできるユーザー］を「全員」にして、新しいバージョンでデプロイし直す |
| 直したはずの動きにならない | デプロイのし直し（`デプロイを管理` → 鉛筆 → 新しいバージョン） |
| 1RMが「体重未入力のため採点対象外」 | 測定画面の体重を入れてください。1RMは体重比で採点します |
