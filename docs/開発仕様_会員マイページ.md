2026-10-17。ユーザーとの合意を記録する。既存 HANDOFF.md の将来計画より本書を優先する。

## 確定している方向

- needs-athcheck と physical-check は別アプリとして維持する。統合やモード追加はしない。
- 一般用のログイン・権限・会社別設定の設計を参考に、アスチェックへ実装する。
- 現行の30種目・40入力欄、採点、ボディマップ、部門別表示、推移を維持する。
- トレーナーが登録・測定を行い、会員は本人のマイページで最新結果・履歴・進捗を見る。
- 教材は測定結果から候補提示し、トレーナーが確定して本人へ公開する。
- 一般用も将来は本人のマイページを持つが、今回の実装対象はアスチェック。
- 10月末（当初の目安10/30）の商談に向け、架空データで一連の操作を実演する。

## デモまでの順序と完了条件

1. 採点の保全：現行版と同一の入力・基準で全出力が一致する。0点、片側、未測定、境界値を確認。
2. 認証・保存基盤：アスチェック専用の開発環境でスタッフ・本人を分離。別会社・別会員へのアクセスをDB側で拒否。
3. マイページ：最新・測定日一覧・当時の詳細・現行基準による推移。内部メモを返さない。
4. 項目設定：項目の有効化・追加・基準変更。過去の入力定義を保持し、変更で過去の単位や入力形式を読み替えない。
5. 教材：少数の承認済みルールと教材で候補→トレーナー確定→本人表示まで通す。
6. 通し確認：820px/390px、招待・再ログイン・保存・履歴・権限・教材公開を確認。

## 実装案（外部環境の設定前に確認する項目を含む）

- 一般用と同様に認証付きのサーバーとDBを用意するが、接続先は独立させる。
- メール招待制を初期案とする。本人ログイン方式と保護者閲覧は未確定。
- 会員プロフィールと認証ユーザーの対応は管理側で作る。自己申告の権限では管理者にしない。
- 会社ID・会員ID・測定IDで管理する。名前や教材名を紐付けのキーにしない。
- 会員へ公開するコメントとスタッフ用メモは別の項目にする。
- 現行の実測値と保存時スコアを保持する。推移は実測値を現行基準で再計算する。
- 体重と推定フラグは測定回に属する。現在のプロフィールの体重で過去を採点しない。
- 会員向け履歴は認証を必須とし、既存共有リンクの仕組みをそのまま本人認証として流用しない。
- 本番スプレッドシートへの書込み、一括移行、公開先切替はこの初期作業に含まない。

## 教材との対応

候補抽出と公開を分ける。候補だけで会員画面へ表示しない。

| 属性 | 例・用途 |
|---|---|
| 教材ID | Method Book側の既存ID。名称変更でも維持 |
| 部位タグ | 股関節、肩関節など |
| 目的タグ | 柔軟性、ジャンプなど |
| 教材種別 | エクササイズ／測定方法／スタッフ研修 |
| 実施条件 | 器具、難易度、指導要否 |
| 監修・公開状態 | 未監修を会員向け候補から除く |
| 会社の利用可否 | 自社教材や導入先教材の閲覧範囲 |

股関節・CMJの具体的な教材IDと条件は未登録。初回のコードは架空教材だけで動作検証する。
本番用の対応表は教材の中身を確認してから作成し、トレーナーの監修を経て有効にする。
最大2件を固定の優先順位で提示する。未測定は条件不成立、0点は人の判断に戻す初期案とする。
回数・頻度・本人向け説明はトレーナーが設定する。低い総合点だけでCMJの必要性を断定しない。
独自の測定項目には、ボディマップやジャンプ分析の意味付けを自動付与しない。
